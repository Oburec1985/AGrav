# Инструкция для ИИ по работе с долговременной памятью (MemoryDB)

Эта инструкция описывает правила управления базой знаний и семантической памятью. Любой ИИ-ассистент, работающий в этом репозитории, обязан следовать этим правилам.

---

## 1. Разделение памяти (Когда и куда сохранять данные)

### 1.1. Оперативная память (Текущие чек-листы)
Хранится в файлах `cach/plan.md` и `cach/notes_last_state.md` внутри проектов.
- **Что заносить**: Информацию, нужную только для текущей сессии разработки (какие файлы изменены, какие локальные задачи выполнены, временные комментарии по коду).
- **Запрещено**: Добавлять в долговременную базу Qdrant/JSON мелкие локальные шаги (например, "добавил импорт в main.py").

### 1.2. Долговременная память (Глобальные факты)
Хранится в `MemoryDB` (инструменты `save_memory_fact`, `search_memory_facts`).
- **Что заносить**: Обобщенные правила разработки, технические нюансы, особенности компиляторов, важные соглашения по кодированию в проектах, архитектурные решения.
- **Критерий добавления**: Будет ли этот факт полезен в будущем на другом проекте или при рефакторинге текущего через месяц? Если да — сохраняем.

---

## 2. Связывание с Obsidian и предотвращение дублирования

Вся база знаний является частью Obsidian-хранилища. Чтобы избежать создания дубликатов информации на диске, придерживайтесь алгоритма:

### 2.1. Чтение заметок Obsidian
Перед началом работы с любой заметкой Obsidian (`.md` файл):
1. Прочитайте первые строки файла и найдите YAML Frontmatter (блок между `---`).
2. Проверьте наличие поля `memory_id`.
   - Если `memory_id` присутствует, значит, этот файл **уже проиндексирован** в MemoryDB. **Не индексируйте его повторно!**
   - Вы можете использовать поиск `search_memory_facts` по этому `memory_id`, чтобы найти связанные векторы в Qdrant.

### 2.2. Индексация новой заметки Obsidian
Если вы создали новую архитектурную заметку, инструкцию или нашли важное решение и хотите зафиксировать его:
1. Вычлените из текста **краткую, емкую суть** (концентрат знаний, 1–3 предложения).
2. Вызовите инструмент `save_memory_fact`, передав:
   - `fact`: выжимка факта.
   - `tags`: список меток.
   - `project_context`: имя текущего проекта.
3. Инструмент вернет UUID сохраненной записи и запишет `.json` файл в `data/records/`.
4. Впишите этот UUID в начало исходного `.md` файла в Obsidian в формате YAML Frontmatter:
   ```yaml
   ---
   memory_id: <полученный_UUID>
   indexed_at: <текущая_дата_и_время_ISO>
   ---
   ```

### 2.3. Исключение дублирования кода и текста
- **Никогда** не сохраняйте весь текст большой заметки или файлы исходного кода целиком в `save_memory_fact`. 
- Сохраняйте только **выжимку (саммари) правил** и в метаданных/тексте факта обязательно указывайте относительный путь к файлу источника (например: `source_file: "20_Проекты/MemoryDB/docs/README.md"`).

---

## 3. Обновление и удаление данных

### 3.1. Корректировка фактов
- Если вам нужно исправить факт, отредактируйте его JSON-файл в `data/records/<uuid>.json` напрямую. Настройки синхронизации автоматически обновят вектор в Qdrant при следующем старте.
- Также можно обновить текст заметки в Obsidian, не трогая её `memory_id`.

### 3.2. Удаление фактов
- Если факт устарел, удалите его через `delete_memory_fact(uuid)`. Это удалит его JSON-файл с диска и сотрет вектор из базы.
- Если вы удаляете файл заметки `.md` в Obsidian, убедитесь, что удалили и соответствующий JSON-файл в `data/records/<uuid>.json` (или воспользуйтесь скриптом автоочистки `src/cleanup.py`).
