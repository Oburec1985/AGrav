# 🛠️ Регламент эксплуатации ALF в Amvera

Этот документ содержит инструкции по управлению проектом ALF (Active Lost & Found) в облаке Amvera.

---

## 🚀 Запуск и Остановка системы

Система состоит из двух независимых проектов в Amvera: **alf-backend** и **alf-frontend**.

### Как запустить/остановить:
1. Зайдите в панель [Amvera Cloud](https://amvera.ru).
2. Выберите нужный проект (`alf-backend-oburec` или `alf-frontend-oburec`).
3. Используйте кнопки **"Запустить"** или **"Остановить"** в верхнем меню управления.
4. **Важно**: Бэкенд должен быть запущен первым, так как фронтенд при сборке обращается к нему.

---

## 🔄 Синхронизация кода (Local -> Amvera)

Так как проект использует Docker, синхронизация происходит через отправку файлов.

### Вариант А: Через Git (Рекомендуемый)
1. Добавьте удаленный репозиторий Amvera (ссылка есть в настройках проекта Amvera):
   ```bash
   git remote add amvera-backend https://git.amvera.ru/oburec/alf-backend-oburec
   git remote add amvera-frontend https://git.amvera.ru/oburec/alf-frontend-oburec
   ```
2. Отправьте изменения:
   ```bash
   git push amvera-backend master
   git push amvera-frontend master
   ```

### Вариант Б: Через ZIP (Если Git не настроен)
1. В корне проекта ALF уже есть `backend.zip` и `frontend.zip`.
2. В панели Amvera выберите "Загрузить файлы" -> Выберите соответствующий ZIP.
3. Система автоматически начнет пересборку Docker-образа.

## 🛠️ Администрирование и Модерация

### Доступ в админ-панель
Админка доступна только пользователям с флагом `is_admin: true`.
1. Авторизуйтесь на сайте под своей учеткой.
2. Кликните на имя в шапке -> **Профиль** -> Кнопка **"Админ-панель"**.

### Проверка статуса (System Health)
В админ-панели есть блок **System Health**. Он показывает:
- **CPU/RAM**: Если нагрузка > 80%, Amvera может убить процесс. Увеличьте тариф или RAM в настройках.
- **DB Connections**: Если 5/5, значит пул переполнен.

## ⚠️ Решение проблем (Почему не собиралось?)

Раньше проект мог не собираться по следующим причинам (исправлено):
1. **Библиотеки анимаций**: `framer-motion` вызывал ошибку в `node-alpine` (удален).
2. **Хардкод IP**: В коде был прописан `127.0.0.1`. Теперь система использует переменные `BACKEND_URL` и `NEXT_PUBLIC_API_URL`.
3. **Порты**: Amvera ожидает ответ на порту, указанном в `amvera.yml`. Теперь это синхронизировано.
