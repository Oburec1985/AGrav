# Инструкция по использованию .env в проекте ALF

Использование файла `.env` — это стандарт безопасности и удобства. Он позволяет хранить все секретные данные (пароли, ключи) в одном месте и не "засвечивать" их в основном коде или конфигурации Docker.

## Что я сделал:
1. **Создал файл `.env`**: Теперь все ваши настройки (база данных, почта, телеграм) находятся там.
2. **Обновил `docker-compose.yml`**: Теперь вместо открытых паролей там используются ссылки на переменные (например, `${SMTP_PASSWORD}`).

---

## Как правильно работать с .env

### 1. Безопасность (Самое важное!)
Никогда не добавляйте файл `.env` в Git. Если вы используете GitHub/GitLab, убедитесь, что `.env` прописан в файле `.gitignore`. 
*Для других разработчиков обычно создают файл `.env.example` с пустыми значениями.*

### 2. Применение изменений
Docker Compose автоматически подхватывает файл `.env`, если он лежит в той же папке. Чтобы изменения вступили в силу, нужно перезапустить контейнеры:

```powershell
docker-compose down
docker-compose up -d
```

### 3. Формат записи
*   В `.env` файле **необязательно** использовать кавычки, если в значениях нет пробелов.
*   **DATABASE_URL**: Обратите внимание, что если вы меняете пароль в `POSTGRES_PASSWORD`, его нужно обновить и в строке подключения `DATABASE_URL`.

### 4. Особенности Mail.ru
Если отправка почты выдает ошибку "Authentication failed":
1. Зайдите в Mail.ru -> Настройки -> Безопасность.
2. Найдите "Пароли для внешних приложений".
3. Создайте новый пароль (назовите его "ALF App").
4. Скопируйте полученный код и вставьте его в `.env` в поле `SMTP_PASSWORD`.

---

## Как проверить, что всё подхватилось?
Вы можете выполнить команду, чтобы увидеть итоговый конфиг, который собрал Docker:
```powershell
docker-compose config
```
В выводе вы должны увидеть свои реальные пароли вместо `${...}`.
