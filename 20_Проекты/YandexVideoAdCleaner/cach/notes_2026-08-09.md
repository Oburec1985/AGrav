# Заметки 2026-08-09

## Контекст

Пользователь попросил сделать расширение для Яндекс Браузера, удаляющее рекламу на странице Яндекс Видео.

## Решение

Сделано распакованное Manifest V3 расширение. Основной механизм: `declarativeNetRequest` для блокировки рекламных запросов, плюс content script и CSS для скрытия рекламных DOM-элементов, которые появляются динамически.

## Риск

Верстка и рекламные URL Яндекса могут меняться. Для поддержки нужно дополнять `rules.json` и селекторы в `styles.css`/`content.js` по фактическим признакам новых рекламных блоков.

## Исправление JWPlayer-рекламы

Пользователь прислал HTML кнопки пропуска:
`<div class="jw-skip jw-reset jw-skippable" ... aria-label="Пропустить">...`

Добавлена отдельная обработка JWPlayer:
- поиск `.jw-skip`, `.jw-skiptext`, `[aria-label*="Пропустить"]`;
- синтетический клик по кнопке пропуска;
- внедрение `injected.js`, который вызывает `jwplayer(...).skipAd()` в контексте страницы;
- частый watchdog 100 мс: ждёт разблокировку `jw-skippable`, кликает после таймера, ускоряет/перематывает рекламный video при тексте `Реклама закончится`;
- CSS-скрытие JWPlayer ad-контейнеров.

## Исправление по полному HTML jw-wrapper

В HTML найден рекламный media-источник `https://cdn.lotory.top/1x/Book_of_Dead.mp4`, контейнер `#player_box_vast` / `.jw-plugin-vast`, таймер `jw-text-alt` и реальная обертка `.jw-wrapper` без видимого родителя `.jwplayer`.

Изменения:

- обработка JW расширена на `.jw-wrapper`;
- рекламное video с `lotory.top` останавливается, очищается `src`, вызывается `load()`;
- VAST-контейнеры скрываются CSS.

## Исправление повторной установки src

Новый HTML показал другой файл на том же домене: `https://cdn.lotory.top/1x/bookOfRa2.mp4`. Значит реклама ротируется по файлам.

Изменения:
- `lotory.top` добавлен в `host_permissions`;
- DNR-правила для `lotory.top` получили `resourceTypes: other`;
- добавлен перехват `HTMLMediaElement.prototype.src` и `Element.prototype.setAttribute('src', ...)`, чтобы JWPlayer не мог заново назначить рекламный `cdn.lotory.top` на video.

## Исправление совместимости с Яндекс Браузером

Новый HTML показал `https://cdn.lotory.top/1x/bookRa.mp4`: домен тот же, но рекламный `src` продолжает появляться. Возможная причина - несовместимость `content_scripts.world = MAIN` или подстановка через вложенный `<source>`.

Изменения:
- удален `world: MAIN` из `manifest.json`;
- `injected.js` снова внедряет page-script через DOM, чтобы код точно выполнялся в контексте страницы;
- добавлен перехват `HTMLSourceElement.prototype.src`;
- `blockMediaElement()` теперь чистит не только `video[src]`, но и вложенные `source[src]`;
- при срабатывании пишется диагностический атрибут `data-yvac-last-blocked-src`.

## Embed-домен nmcorp.video

Полный HTML от `<html>` показал, что рекламный JWPlayer живет не в документе `yandex.ru/video`, а во вложенном embed-документе `nmcorp.video` (`<title>Embed Player</title>`, `/static/players/8.34.5/vast.js`, `jwplayer("player_box")`).

Изменения:
- `nmcorp.video` и `*.nmcorp.video` добавлены в `host_permissions`;
- content scripts добавлены на `nmcorp.video/*` с `all_frames: true`;
- добавлен перехват глобального `window.jwplayer`, чтобы удалить `advertising` из конфигурации до `player.setup(...)`;
- при удалении рекламной конфигурации ставится диагностический атрибут `data-yvac-ad-config-removed`.

## Yastatic sandbox iframe

Пользователь прислал внешний блок `VideoPlayer-Sandbox`: Яндекс создает iframe на `yastatic.net/video-player/.../iframe-default.html`, а URL `nmcorp.video/player/...` передается внутрь через hash-параметр `html`.

Изменения:
- `*.yastatic.net` добавлен в `host_permissions`;
- content scripts добавлены на `*.yastatic.net/video-player/*` с `all_frames: true`;
- добавлен диагностический маркер `data-yvac-yastatic-frame`;
- добавлена DNR-блокировка `vast.js` на `nmcorp.video` при сохранении allow-правил для основных скриптов JWPlayer.

## MAIN world для nmcorp

Новый полный HTML не содержит маркеров `data-yvac-*`, а `https://nmcorp.video/static/players/8.34.5/vast.js` остается в документе. Значит DOM-инъекция вероятно блокируется CSP embed-плеера, либо скрипт не выполняется в page-world достаточно рано.

Изменения:
- для `injected.js` включен `world: MAIN` при сохранении узкого scope `yandex.ru/video`, `yastatic.net/video-player`, `nmcorp.video`;
- `injected.js` теперь исполняется напрямую как content script, без вставки inline `<script>`;
- добавлен диагностический маркер `data-yvac-injected`;
- DNR-условие `vast.js` переведено с `domains` на `requestDomains`.
