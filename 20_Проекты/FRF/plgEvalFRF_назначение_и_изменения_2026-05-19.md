﻿# plgEvalFRF: назначение и изменения за последнюю неделю

Дата: 19.05.2026

## Назначение плагина

`plgEvalFRF` - плагин Recorder для обработки ударных испытаний лопаток и расчета частотных характеристик по измеренным каналам.

Плагин решает несколько связанных задач:

- находит удары по тахо/силовому датчику или, в новом режиме, по первому датчику обратной связи;
- нарезает временные блоки ударов и синхронизирует их с измерительными каналами;
- считает спектры, FRF, когерентность и SPM-представление;
- ищет экстремумы/резонансные пики в заданных полосах частот;
- визуально показывает осциллограмму, спектры, полосы, флаги и список найденных экстремумов;
- ведет настройки расчета, отображения, осей, поиска ударов и параметров отчета;
- формирует Excel-отчет по выбранной лопатке, включая серийный номер, вес и силу зажатия.

Основной пользовательский сценарий: оператор выбирает каналы, настраивает поиск удара и полосы, запускает запись/обработку, проверяет что удары и полосы найдены корректно, после чего формирует отчет по лопатке.

## Что изменяли за последнюю неделю

### Форма экстремумов `uPeakFrm`

- Добавлена отдельная форма списка экстремумов, открываемая с главной формы через чекбокс `Экстремумы`.
- В таблицу выводятся частота, амплитуда, декремент и индекс отсчета.
- Найденные пики в сконфигурированных полосах подсвечиваются зеленым.
- Пики рядом с границей полосы подсвечиваются бледно-желтым, чтобы было видно спорные попадания.
- Добавлена цветная индикация полноты поиска полос: зеленая, если все полосы найдены, красная, если часть полос не найдена.
- Сообщение о незаданном триггере заменено на статусную метку на форме, чтобы не плодить всплывающие сообщения во время работы.
- Добавлена временная кнопка/лог диагностики расчета пиков; отладочные строки помечены `PEAK_DEBUG`.

### Контроль качества найденных ударов по полосам

- На форму экстремумов добавлен индикатор отношения `мин/макс` для главных максимумов по разным сконфигурированным полосам.
- Соотношение считается не по всем зеленым пикам подряд, а по одному главному максимуму на каждую найденную полосу.
- Если в одной полосе найдено несколько пиков, например 135 Гц и 300 Гц, они не сравниваются между собой для этого критерия.
- Добавлен пороговый ограничитель отношения `мин/макс`.
- Если отношение ниже порога, удар на форме считается не найденным, даже если формально экстремумы по полосам есть. Это защищает от ситуации, когда оператор слишком занизил порог и поймал шумовой удар.
- Порог отношения сохраняется в настройках как `PeakRatioLimit`.

### Серийный номер и параметры лопатки

- Добавлена проверка серийного номера перед созданием отчета.
- Если лопатка выбрана, но серийный номер не задан, поле подсвечивается и отчет не создается.
- Добавлен сценарий поиска лопатки по введенному серийному номеру через Enter.
- При смене номера лопатки серийный номер записывается только если он не пустой и не занят другой лопаткой.
- Добавлена защита от случайного назначения одного серийного номера разным лопаткам.

### Excel-отчет

- На главную форму добавлено поле силы зажатия `FPressFE`.
- В Excel-отчет добавлена строка `F` со значением силы зажатия под строкой серийного номера.
- Передача параметров отчета обновлена так, чтобы сила зажатия попадала в генератор отчета вместе с остальными данными лопатки.

### Режим `Без датчика силы`

- В настройках обработки добавлен чекбокс `Без датчика силы` (`NoTahoCb`).
- В этом режиме отдельный тахо/силовой датчик не используется.
- Источником для поиска удара становится первый датчик обратной связи из списка сигналов.
- Для режима без датчика силы принудительно используется SPM-расчет; FRF и Coh не считаются.
- Родительский узел в дереве настроек показывает `Без датчика силы`, когда режим включен.
- При снятии галки выбранный в `TahoNameCB` датчик снова записывается в тахо-узел и отображается по имени.
- Исправлено первое открытие формы: `TahoNameCB` теперь показывает имя тахо-датчика, если режим без датчика силы выключен.
- При программном заполнении формы отключаются обработчики `OnChange/OnClick`, чтобы они не затирали настройки до загрузки сохраненных значений.

### Поиск удара без датчика силы

- Поиск удара работает через тот же автомат состояний, что и обычный режим: `TrOff`, `TrRise`, `TrFall`, `TrEnd`.
- В режиме без датчика силы порог применяется к отклонению сигнала от базового уровня канала обратной связи.
- Базовый уровень считается по началу текущего буфера, чтобы убрать постоянное смещение.
- Добавлен временный лог `NO_TAHO_DEBUG` для диагностики состояния автомата, уровня базы, максимального отклонения и завершения удара.
- Для первого датчика обратной связи в режиме без датчика силы исключена лишняя повторная обработка как отдельного тахо-канала.

### Сохранение амплитуды события `ThresholdFE`

- Исправлено сохранение амплитуды события из настройки `ThresholdFE`.
- Для режима с датчиком силы и режима без датчика силы теперь хранятся независимые значения:
  - `Threshold` - порог поиска события в обычном режиме;
  - `NoTahoThreshold` - порог поиска события в режиме без датчика силы.
- При переключении галки `Без датчика силы` текущее значение сохраняется в параметр старого режима, а в edit подставляется значение нового режима.
- При закрытии формы активный порог дополнительно переносится в соответствующий параметр объекта обработки.
- Перед `SaveSettings` активное значение также синхронизируется с нужным сохраненным полем, чтобы ini-файл получил актуальные данные.
- Исправлена причина затирания значения нулем при первом показе формы: программное выставление `TahoNameCB` и `NoTahoCb` больше не запускает обработчики режима до заполнения `ThresholdFE`.

## Файлы, которые затрагивались

- `forms/uEvalFRFFrm.pas` и `forms/uEvalFRFFrm.dfm` - основная форма, настройки, поиск удара, сохранение/загрузка параметров, режим без датчика силы, сила зажатия.
- `forms/uEditEvalFRFFrm.pas` и `forms/uEditEvalFRFFrm.dfm` - форма настройки обработки ударов, `NoTahoCb`, `TahoNameCB`, независимые пороги `ThresholdFE`.
- `forms/uPeakFrm.pas` и `forms/uPeakFrm.dfm` - список экстремумов, индикация полос, отношение `мин/макс`, порог качества удара.
- `units/uBladeReport.pas` - вывод силы зажатия в отчет.
- `log/log.txt` - рабочий лог диагностики.

## Временная отладка, которую потом стоит убрать

В коде пока остаются диагностические места:

- `DebugNoTahoLog` и строки `NO_TAHO_DEBUG` в `forms/uEvalFRFFrm.pas`;
- строки `PEAK_DEBUG` в расчете экстремумов;
- временные записи в `log/log.txt`.

Их лучше удалить отдельной чистовой правкой после того, как режим без датчика силы и критерий `мин/макс` будут проверены на реальных испытаниях.
