# RecorderLnx: план первой итерации

## Цель первой итерации

Создать минимальное ядро без UI-сложности и без реальных драйверов, чтобы проверить модель состояний, источников данных, тегов, событий и тест-примеров.

## Итерация 0: документация и каркас

- [x] Создать каталог проекта в AGrav.
- [x] Описать назначение и архитектуру.
- [x] Составить первую карту интерфейсов Windows Recorder.
- [ ] Создать реальный Lazarus/FPC репозиторий/каталог исходников RecorderLnx.
- [ ] Выбрать структуру каталогов исходников: `src/core`, `src/tags`, `src/sources`, `src/ui`, `src/plugins`, `tests`.

## Итерация 1: состояние приложения

Первый реализуемый класс: `TRecorderStateMachine`.

Требования: состояния `Stop`, `View`, `Record`; проверка допустимости переходов; событие изменения состояния; запрет конфигурации вне `Stop`; текстовое описание текущего состояния.

Пример/тест: создать машину состояний; пройти `Stop -> View -> Record -> View -> Stop`; проверить, что недопустимый переход отклоняется; вывести журнал переходов.

## Итерация 2: теги и сигнальный буфер

Классы: `TTag`, `TTagRegistry`, `TSignalBuffer`.

Пример/тест: создать 3 тега; добавить данные в буфер; получить снимок; проверить поиск по имени и id.

## Итерация 3: mock-источник данных

Классы: `IDataSource`, `TMockSineDataSource`, `TDataSourceThread` или безопасный прототип без отдельного thread на первом шаге.

Пример/тест: источник генерирует синус/счётчик с `UpdateTime`; публикует `TDataFrame`; registry обновляет теги; событие `OnDataUpdated` вызывается ожидаемое число раз.

## Итерация 4: минимальный UI

- Главное окно Lazarus.
- Кнопки `Stop`, `View`, `Record`.
- Дерево источников/тегов.
- Один простой формуляр отображения текущих значений.

Пример/тест: запуск mock-источника; отображение значений без прямого доступа worker thread к UI; остановка без зависания.

## Итерация 5: запись данных

- Минимальный writer в текстовый/CSV/бинарный временный формат.
- Flush/close при `Record -> View` и `Record -> Stop`.
- Метаданные кадра записи.

Формат записи окончательно не утверждать до анализа совместимости с существующим Recorder/MERA.
