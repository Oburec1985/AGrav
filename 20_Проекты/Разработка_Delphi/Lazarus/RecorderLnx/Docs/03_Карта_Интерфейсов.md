# RecorderLnx: карта интерфейсов Windows Recorder

Источник: `D:\works\OburecGH\recorder\SharedRUnits\interfaces`.

Эта карта нужна, чтобы при проектировании RecorderLnx не дублировать уже найденные сущности и не терять функционал Windows Recorder. Это не требование переносить COM API один к одному. Это функциональный каталог.

### uRecorderStateMachine / TRecorderStateMachine

- Путь: `D:\works\OburecGH\Lazarus\RecorderLnx\Core\uRecorderStateMachine.pas`.
- Назначение: минимальная модель режимов RecorderLnx по руководству Recorder: `Stop`, `PreviewArmed`, `Preview`, `RecordArmed`, `Record`.
- Слой: Core/domain, без LCL и без привязки к каналам, устройствам или файловой записи.
- События/методы: `StartPreview`, `StartRecord`, `StartConditionMet`, `Stop`, `OnStateChanged`.
- Условия старта первой версии: `Manual`, `SignalLevel`, `ExternalTrigger`, `Time`. Неручные условия переводят машину в `PreviewArmed` или `RecordArmed` до вызова `StartConditionMet`.
- Разрешенные переходы первой версии: `Stop -> Preview/PreviewArmed`, `Stop -> Record/RecordArmed`, `Preview -> Record/RecordArmed`, любой активный/armed режим -> `Stop`.
- Ошибки: неверный переход выбрасывает `ERecorderStateError`.
- Пример/тест: `D:\works\OburecGH\Lazarus\Tests\RecorderTests\StateMachine\RecorderStateMachineTest.lpr`.
- Статус: реализовано, документировано в коде и проверено на Windows через FPC 3.2.2.

### Правило перехода Record -> Preview

- `TRecorderStateMachine.StartPreview(rscManual)` разрешен из состояния `rsRecord`.
- Смысл перехода: запись текущего кадра/каталога завершается, но режим сбора и просмотра остается активным.
- Следующий `StartRecord` должен создаваться уже как новый кадр записи (`0001`, `0002`, ...); сама файловая логика будет реализована отдельным storage/session layer поверх state machine.
- Пример/тест: `D:\works\OburecGH\Lazarus\Tests\RecorderTests\StateMachine\RecorderStateMachineTest.lpr`.
