# Проект CoachPay (Android)

Приложение для автоматизации учета оплат учеников спортивных секций, классов или кружков.

## Цели проекта
- Упростить тренеру/преподавателю учет полученных средств.
- Дать возможность ученикам/родителям быстро отправлять отчеты об оплате по уникальному ID тренера.
- Минимизировать время на рутину с должниками за счет автоматической генерации списков для мессенджеров.

## Архитектура хранения данных
Для обеспечения простоты, быстроты работы и легкости миграций локальная реляционная БД заменена на **сериализацию в JSON**:
- Все данные приложения хранятся в едином древовидном JSON-файле во внутреннем хранилище приложения (`Context.filesDir`).
- Чтение и запись осуществляются с помощью библиотеки `kotlinx.serialization`.
- Для сетевой синхронизации и резервного копирования используется облако (Firebase/Firestore) в виде аналогичных документо-ориентированных структур.

## Структурное дерево учеников
Данные организованы в иераххическую структуру:
- **Корень (AppState)**
  - **Города** (Москва, Мытищи, Королёв...)
    - **Группы / Классы** (Авангард, Старт, Про...)
      - **Ученики** (Фамилия, Имя, ID, monthlyFee)
        - **Оплаты** (сумма, месяц, статус: оплачено/не оплачено, дата подтверждения, название/title)

## Основной функционал

### 1. Управление и навигация по дереву
- Просмотр, добавление, удаление и редактирование узлов любого уровня (Города, Группы, Ученики).
- Адаптивный и "крупный" UI для удобного попадания по кнопкам и элементам списка пальцем на ходу.

### 2. Календарь и Учет Оплат
- Помесячный учет оплат по каждому ученику.
- Автоматический перенос задолженностей и переплат на следующий месяц (в разработке).
- Добавление платежей по сумме или по имени.
- Отметка о платеже в один тап.

### 3. Быстрый поиск
- Поиск ученика по подстроке во всей базе или конкретной группе.
- Переключение статуса оплаты ("Оплачено" / "Не оплачено") прямо из списка результатов поиска.

### 4. Генератор списков должников и экспорт в буфер
- Сбор всех учеников группы без отметки об оплате за выбранный месяц (включая неоплаченные внемесячные долги).
- Кнопка **"Скопировать должников"** (`ContentCopy` в панели группы) формирует структурированный список в формате:
  `ФИО: платеж1 (мес) сумма, платеж2 сумма; потом перенос строки и след. ученик`
  *Пример:*
  `Скрипник Марк: Абонемент (Июнь 2026) 3000 ₽, Форма 1500 ₽`
- Текст мгновенно копируется в буфер обмена системы Android для удобной отправки в чаты мессенджеров (WhatsApp/Telegram).

### 5. Сетевой обмен (Тренер - Ученик)
- **Ученик**:
  - Привязывается к тренеру по его ID.
  - Отправляет уведомление об оплате с указанием суммы.
- **Тренер**:
  - Получает уникальный ID.
  - Видит входящий пул уведомлений об оплате.
  - Подтверждает оплату в один тап.

## Реализация логики оплат и календаря (Июнь 2026)

### 1. Периодические оплаты (Абонемент)
- У каждого ученика задается параметр `monthlyFee: Double` (по умолчанию 3000.0) — стоимость ежемесячного абонемента.
- При переключении месяца в календаре (стрелки влево/вправо) приложение проверяет наличие абонемента на этот месяц для всех учеников группы. Если его нет, он генерируется автоматически со статусом `UNPAID` и суммой `monthlyFee` ученика.
- Если тренер меняет размер абонемента (`monthlyFee`) для ученика, эта сумма применяется только к будущим месяцам (при их первом открытии). Суммы в уже сгенерированных месяцах сохраняются в исходном виде.

### 2. Разовые оплаты
- Разовые оплаты создаются вручную для конкретного ученика на выбранный в календаре месяц.
- Тренер указывает название (например, "Форма", "Турнир") и произвольную сумму.
- Эти оплаты не повторяются в последующих месяцах и служат для учета разовых целевых взносов.

### 3. Отметка оплат в один тап
- В списке учеников отображаются все платежи (абонемент + разовые) за выбранный месяц.
- Каждая оплата является крупной интерактивной кнопкой. Нажатие на нее переключает статус между `PAID` (оплачено, зеленая галочка) и `UNPAID` (не оплачено, серая галочка).
- Изменения мгновенно сериализуются в JSON-файл в `Context.filesDir` с созданием резервной копии (`.bak`).

## Протокол резервного копирования исходного кода (Backup Protocol)
* **Обязательные бэкапы перед рефакторингом**: Перед выполнением любых масштабных изменений исходного кода или рефакторинга структуры классов, AI обязан создать ручной бэкап (слепок изменяемых файлов) в директорию `c:\Oburec\Antigravity\Projects\bu\`.
* **Сохранность базы данных**: Категорически запрещено удалять, перезаписывать или сбрасывать локальную базу данных (включая файлы учеников Королёв, Мытищи и т.д.) без явного согласия пользователя. Использование unit-тестов не должно приводить к затиранию рабочих данных пользователя.
