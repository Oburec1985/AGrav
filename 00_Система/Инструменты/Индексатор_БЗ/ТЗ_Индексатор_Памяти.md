# 📝 ТЗ: Векторный Индексатор Базы Знаний AGrav (MemoryDB)

## 1. Введение и Бизнес-Цель
В процессе работы ИИ-агентов (Cursor/Gemini) с базой знаний (БЗ) **AGrav** часто возникает проблема **context rot** и высокого потребления токенов. Чтение файлов заметок целиком расходует лимиты контекстного окна и снижает точность работы моделей.

**Цель разработки**:
Интегрировать локальную векторную базу данных Qdrant для семантического индексирования заметок AGrav. ИИ-агент должен выполнять поиск нужного контекста по смыслу и считывать только релевантные фрагменты (чанки) документов вместо файлов целиком.

---

## 2. Архитектура Системы

Система состоит из трех ключевых компонентов:
1. **Служебный блок (YAML Frontmatter)** в начале каждой заметки для отслеживания версий.
2. **Индексирующий скрипт (Vault Indexer)**, выполняющий сканирование, вычисление хэшей и синхронизацию.
3. **MCP-интерфейс и Векторная БД (Qdrant Client + FastEmbed)** для локального хранения и поиска.

```
+-------------------------------------------------------------+
|                     База Знаний AGrav                       |
|  (Папки: 00_Система, 10_Работа, 15_Дом, 20_Проекты и др.)   |
+------------------------------+------------------------------+
                               |
                        [Сканирование]
                               v
+-------------------------------------------------------------+
|             Vault Indexer (vault_indexer.py)                |
|  - Парсит YAML frontmatter                                  |
|  - Считает SHA256/MD5 контента (без служебного блока)      |
|  - Сравнивает хэши -> Выявляет новые/измененные заметки    |
|  - Разбивает заметки на смысловые чанки                     |
+------------------------------+------------------------------+
                               |
                   [Обновление фронтматтера]
                               v
                       [Обновление БД]
                               v
+-------------------------------------------------------------+
|                  Локальный Qdrant Client                    |
|                Коллекция: `vault_notes`                     |
+------------------------------+------------------------------+
                               ^
                       [Семантический поиск]
                               |
+------------------------------+------------------------------+
|                     ИИ-Агент (LLM)                          |
+-------------------------------------------------------------+
```

## 3. Спецификация Служебного Блока Заметки (Frontmatter)

Каждая индексируемая заметка (`.md` файл) должна содержать в самом начале YAML-блок следующего формата:

```yaml
---
memory_id: 3a2c5e7b-1a8c-4f9e-8d63-b152d87e24a8
hash: 5d41402abc4b2a76b9719d911017c592
last_indexed: 2026-07-07T12:30:45.123456
---
```

### Правила обработки блока:
1. **`memory_id`**: Уникальный UUID заметки. Генерируется индексатором при первой обработке файла.
2. **`hash`**: Хэш (MD5) содержимого заметки, вычисляемый **после** закрывающего разделителя `---`. Это исключает изменение хэша при обновлении даты индексации в самом блоке.
3. **`last_indexed`**: Время последнего успешного индексирования заметки в формате ISO 8601 UTC.
4. **Сохранение разметки**: При обновлении блока индексатор должен строго сохранять кодировку файла (UTF-8) и формат переноса строк (`LF` или `CRLF`).

## 4. Алгоритм Индексирования и Чанкинга

Индексатор выполняет обход папок `00_Система`, `10_Работа`, `10_Теория_и_Методы`, `15_Дом`, `20_Проекты`, `30_Библиотека` (исключая временные папки, кэш и саму директорию `MemoryDB`).

### Шаги синхронизации:
1. **Выявление изменений**:
   - Если у файла нет YAML frontmatter или отсутствует `memory_id` -> генерируется новый UUID, файл отправляется на индексацию.
   - Если `memory_id` есть, но вычисленный MD5-хэш контента не совпадает с полем `hash` -> файл отправляется на переиндексацию.
   - Если хэши совпадают -> файл пропускается.
2. **Смысловой Чанкинг (Chunking)**:
   - Заметка разбивается на части по заголовкам Markdown (`# `, `## `, `### ` и т.д.).
   - Заголовок раздела сохраняется в метаданных чанка как `heading` и прикрепляется в начало текста чанка для сохранения контекста.
   - Если размер раздела превышает **3000 символов**, он дополнительно дробится по границам абзацев (`\n\n`) для сохранения семантической компактности.
3. **Удаление устаревших данных**:
   - Индексатор получает список всех `memory_id` из Qdrant.
   - Если в Qdrant найден `memory_id`, которого больше нет среди файлов на диске (файл удален), все чанки с этим `memory_id` удаляются из Qdrant.

## 5. Спецификация MCP Инструментов (API для Агентов)

После запуска MCP-сервера MemoryDB, агенту доступны два новых инструмента:

### 5.1. `sync_vault_notes`
Выполняет сканирование БЗ и синхронизацию с Qdrant на лету.
- **Аргументы**:
  - `dry_run` (bool, необязательный): Если `True`, вернет только отчет об изменениях без записи в БД.
- **Результат**: Текстовое описание: `"Синхронизация завершена. Создано: X, Обновлено: Y, Удалено: Z"`.

### 5.2. `search_vault_notes`
Выполняет семантический поиск по всей базе знаний.
- **Аргументы**:
  - `query` (str): Поисковый запрос на естественном языке.
  - `limit` (int, по умолчанию 5): Лимит результатов.
  - `project_context` (str, необязательный): Фильтр по контексту проекта (например, `"RecorderLnx"`).
- **Результат**: Список словарей с полями:
  - `file_path`: Относительный путь к файлу.
  - `heading`: Заголовок раздела.
  - `content`: Текст фрагмента.
  - `score`: Степень соответствия запросу (косинусное сходство).

## 6. Правила для ИИ-Агентов по Экономии Токенов

При решении любой задачи ИИ-агент должен следовать правилам:
1. **Сначала поиск**: Перед тем как читать файл заметки через `view_file` (особенно если он превышает 100 строк), выполните семантический поиск через `search_vault_notes`.
2. **Чтение по частям**: Используйте найденные фрагменты для быстрого ответа. Если контекста чанка не хватает, прочитайте конкретный диапазон строк файла по ссылке `file_path` вместо чтения всего файла.
3. **Обновление индекса**: Если вы отредактировали или создали заметку в AGrav, вызовите `sync_vault_notes()`, чтобы обновить векторный индекс и сделать изменения доступными для поиска.
